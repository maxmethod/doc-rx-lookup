## Step 1 — Place fields on the same step as their widget

The widget writes into GHL's `[data-q="<key>"]` element, which **only exists if that field is on
that step**. Fields can be **hidden**. Group them like this:

| Widget (Custom Code element id) | Fields to add to that step |
| --- | --- |
| `provider-lookup-widget` | `providers_json`, `providers_summary` |
| `medications-lookup-widget` | `medications_json`, `medications_summary` |
| `coverage-lookup-widget` | `current_coverage_json`, `current_coverage_summary` |
| `income-sources-widget` | `income_json`, `income_summary`, `household_income` |

- **Form** (single page): drop all 4 widgets + all 9 fields on the one page.
- **Survey** (multi-step): if you split widgets across steps, keep each widget together with **its own**
  fields on the same step. A field on a different step than its widget = silent no-save.

## Step 2 — Paste the embed blocks (one Custom Code element per widget)

Each block: the seed `<script type="application/json">` must sit **BEFORE** the embed `<script>`,
and **not** be nested inside the `<div>`.

```html
<!-- Doctors / Providers -->
<div id="provider-lookup-widget" data-primary-color="{{custom_values.brand_primary_color}}"></div>
<script type="application/json" id="provider-lookup-widget-seed">{{ contact.custom.providers_json }}</script>
<script src="https://cdn.jsdelivr.net/gh/maxmethod/doc-rx-lookup@v2.4.2/dist/embed-providers.js"></script>
```

```html
<!-- Medications / Rx -->
<div id="medications-lookup-widget" data-primary-color="{{custom_values.brand_primary_color}}"></div>
<script type="application/json" id="medications-lookup-widget-seed">{{ contact.custom.medications_json }}</script>
<script src="https://cdn.jsdelivr.net/gh/maxmethod/doc-rx-lookup@v2.4.2/dist/embed-medications.js"></script>
```

```html
<!-- Current Coverage -->
<div id="coverage-lookup-widget" data-primary-color="{{custom_values.brand_primary_color}}"></div>
<script type="application/json" id="coverage-lookup-widget-seed">{{ contact.custom.current_coverage_json }}</script>
<script src="https://cdn.jsdelivr.net/gh/maxmethod/doc-rx-lookup@v2.4.2/dist/embed-coverage.js"></script>
```

```html
<!-- Income Sources -->
<div id="income-sources-widget" data-primary-color="{{custom_values.brand_primary_color}}"></div>
<script type="application/json" id="income-sources-widget-seed">{{ contact.custom.income_json }}</script>
<script src="https://cdn.jsdelivr.net/gh/maxmethod/doc-rx-lookup@v2.4.2/dist/embed-income.js"></script>
```

The seed line is safe to leave in for new contacts — unresolved `{{...}}` / empty is ignored.

## Step 3 — Don't trip on these (learned the hard way)

1. **Seed before embed, outside the div** — see Step 2. A seed nested in the `<div>` or placed after
   the embed won't hydrate.
2. **The returning-contact seed is same-browser only.** It resolves from the visitor's local-storage
   of a prior submission on that funnel — not a server-side identity lookup. On a brand-new surface it
   does nothing until someone submits and returns in the same browser. Expected; harmless.
3. **Household income is auto-totaled.** `household_income` is written only when ≥1 income source is
   entered, so it won't clobber a manually-entered value.

## Step 4 — Validation "done" checklist

- [ ] Submit as a **test contact** → open the contact record → all 9 fields populated.
      - This is where the **`providers_summary` fix proves out** — the field exists now; last time it
        was missing from the step. Confirm every `_summary` field populated, not just `_json`.
- [ ] **View Source** on the live survey/form → each seed `<script id="…-seed">` shows resolved JSON
      (or is empty for a new contact) — **NOT** the literal `{{ contact.custom.providers_json }}`.
      - If literal → your account's merge syntax differs. Try `{{ contact.providers_json }}`
        (no `.custom.`), or grab the exact token from the merge-field picker, and flag it.
- [ ] Widgets render in **MM purple** (`#6500c1`) — confirms the brand custom value resolved.
- [ ] **Same-browser return test:** submit once, reopen the surface in the same browser → prior entries
      hydrate and new entries **append** (count grows, nothing wiped), and **submit still works**.

## Notes / propagation

- **Fields already synced fleet-wide.** Creating the 9 fields on v4.0 auto-propagated them to every
  sub-account already deployed from the snapshot. A **new form/survey is a funnel asset**, though — it
  only reaches sub-accounts on a fresh snapshot push, not to already-live accounts. For Marsh IG you'll
  build the same net-new surfaces there directly.
- **Legacy intake fields untouched.** `contact.doctors` ("🏥 Doctors"), `contact.provider_list`, and
  `contact.medications` ("🏥 Prescriptions") — where providers/meds were originally wired — are left
  as-is. The widgets standardize on the `_json`/`_summary` keys; old data stays put.
- **Per-account key override (for later, e.g. LPI):** to point a widget at a differently-named field
  without a rebuild, set the config global before the embed:
  ```html
  <script>window.PROV_CONFIG = { fieldKeys: { providers_json: ['<other_key>'] } };</script>
  ```
  Globals: `PROV_CONFIG`, `MEDS_CONFIG`, `COVERAGE_CONFIG`, `INCOME_CONFIG`.
